### Что проверено и держит (кнопки `api/act`)

- **CSRF из браузера закрыт.** `lib/pult/guard.mjs:20-33`: Host (421), только POST, `Content-Type: application/json`
  (простая форма/`text/plain` не проходит — нужен предварительный запрос CORS, а его нет: OPTIONS → 405), Origin ровно
  свой, `Sec-Fetch-Site: same-origin`, токен страницы 32 байта со сверкой без утечки по времени. Чужая страница ни одно из
  трёх (Origin, Sec-Fetch-Site, токен) подделать не может.
- **Перепривязка DNS закрыта:** чужой Host — 421 на всех запросах, включая `GET /` с токеном.
- **Чтение чужой страницей:** CORS-заголовков нет вовсе; ручка звонка закрыта браузеру (`bell-browser`); фреймы запрещены.
- **HTML карточки:** `web/src/md.js` — markdown-it с `html: false`, картинки выключены, ссылки только http(s), затем
  DOMPurify по белому списку; `target=_blank rel=noreferrer`. Проверил стендом в Chromium 16 строк (script, onerror,
  javascript:/data: ссылки, SVG animate, details ontoggle) — исполняемого ничего не выходит.
- **Ввод `api/act`:** `lib/pult/actions.mjs` — белый список полей, формы id/кода/UUID, пределы длины, управляющие символы
  прочь; карточка и проект сверяются с `projects.md` до чтения диска; секрет в тексте Ивана — отказ до записи.
- **git:** `lib/git-read.mjs` — белый список читающих команд, `--output/--ext-diff/--textconv` запрещены; удаление копий —
  только путь из списка git, без `--force`, перед каждым `remove` копия проверяется заново.

### Находки

**Критично** — нет.

**Важно 1. Любой местный процесс нажимает кнопки пульта и пишет слово «от Ивана».**
`lib/web-static.mjs:65` (токен отдаётся в `GET /` любому с правильным Host), `lib/pult/guard.mjs:26,28,30` (Origin,
Sec-Fetch-Site и токен — заголовки, которые не-браузер ставит сам), `lib/pult/routes.mjs:472,487` («кто нажал» по портам
сокета — только записывается в журнал, действие не держит), `lib/pult/board-run.mjs:81` (запись на доску — `--as ivan`).
- Сценарий: тред-агент на том же ноутбуке (у него есть Bash/node) или код, который он запустил (проба, зависимость,
  подсунутая инструкция из чужого текста), делает `GET http://127.0.0.1:4317/` с `Host: 127.0.0.1:4317`, берёт токен из
  `<meta name="vitrina-token">`, затем `POST /api/act` с `Origin: http://127.0.0.1:4317`, `Sec-Fetch-Site: same-origin`,
  `X-Vitrina-Token` и телом `{action:"go"|"yes"|"accept"|"new-card"|…}`. Проходит вся защита §4.1 — ровно так, как это
  делает тест `test/pult.test.mjs:87-99` («исправный»: `pageToken` + `act`). Итог: на карточке запись «го»/«да»/«Принять»
  от Ивана (коммит доски с `Board-As: ivan`), карточка уходит в Done, тред получает звонок с «словом Ивана». Второй щелчок
  Б-дела тоже подделывается: номер первого нажатия приходит в ответе `need-confirm` (`lib/pult/routes.mjs:563`), его же
  шлют как `confirm` (`lib/pult/words.mjs:134`). Страхует только то, что тред по Б-делу переспрашивает «да» в чате;
  у не-Б слов («го», «да», «Принять», «Вернуть», «В работу», «Новая карточка», уборка копий) страховки нет.
- Кто страдает: правило цеха «Кто решил: слово Ивана» — запись на доске и в журнале не отличает Ивана от процесса.
  След есть только постфактум: `client.proc` в `data/vitrina/actions.log` (образ процесса-источника, EXT-89).
- Должно быть так: защита §4.1 рассчитана на браузер — для местных процессов нужен свой барьер. Самый дешёвый, на уже
  готовой отметке EXT-89: для слов, «Принять»/«Вернуть», «Новая карточка» и уборки — **отказ**, если процесс-источник не
  браузер из короткого списка (msedge/chrome/firefox) или определение не удалось (`proc.ok !== true`), а не только запись.
  Это не защита от вредоноса с правами Ивана, но закрывает «тред сам себе сказал го». Если в спеке §4.3 это решено
  осознанно — стоит назвать Ивану явно: «слово с витрины может прийти не от тебя». Спеки (Vault) здесь нет — не проверено,
  что §4.3 так и задумана.

**Важно 2. Ждущий звонка верит любому, кто слушает порт 4317.**
`bell/waiter.mjs:67` (GET без какой-либо сверки сервера), `bell/waiter.mjs:163-180` (сигнал — файл `<bellDir>/<sid>/<id>.ring`,
текст звонка — из ответа сервера, выводится в stderr с кодом 2 = будит тред).
- Сценарий: витрина не запущена (перезапуск, сон ноутбука, упала). Любой местный процесс слушает `127.0.0.1:4317`, кладёт
  файл `W-….ring` в `data/vitrina/bell/<sid>/` (папка открыта на запись пользователю) и отвечает на `/api/bell/<sid>`
  `{ids:[…], text:"…"}` — ждущий будит тред этим текстом в форме звонка от Ивана. Виден в журнале только как строка `ring`.
- Должно быть так: тот же корень, что Важно 1, — полностью без секрета, недоступного местным процессам, не закрыть. Минимум:
  ждущий перед звонком сверяет `/api/health` (`app: VITRINA_APP` и `pid`, совпадающий с владельцем порта) и пишет в
  `bell.log` pid ответившего; текст звонка начинать с номера действия, который тред может сверить с `actions.log`.

**Мелочь 1. Ключи объектов маска не трогает: `unknownWaitingFor` в `/api/health`.**
`lib/mask.mjs:40` маскирует только значения; `lib/threads.mjs:163` кладёт значение `waitingFor` реестра процессов
ключом объекта, `lib/app.mjs:94` отдаёт его в `/api/health` (и в MCP health). Если в `waitingFor` окажется свободный текст
(например, описание запроса разрешения с командой) — он уйдёт без маски. **Не проверено**, бывает ли там свободный текст.
Должно быть так: незнакомое значение — счётчиком под обезличенным ключом (`'?'`) или ключ через `maskText` строгой сетью.

**Мелочь 2. `GET /api/bell/:sid` отдаёт текст Ивана без маски любому местному процессу, знающему sid.**
`lib/pult/routes.mjs:640` — по замыслу (§2.6, браузеру закрыто), но sid тредов видны в журналах и реестре процессов.
Риск невелик (текст — ответ Ивана треду); отмечаю, чтобы решение было явным. Ручка чистая, ничего не пишет.

**Не находки (проверил и отбросил):** повтор нажатия после 403 из `sessionStorage` (`web/src/act.js:38-55`) — тот же
`intentId`, сервер дедуплицирует и сверяет заново; пути в `web-static` — сегменты по белому списку + сверка «внутри dist»;
`withToken` вставляет base64url — инъекции в HTML нет; `config.json` защиту не выключает (`pultSeams` только из тестов).
